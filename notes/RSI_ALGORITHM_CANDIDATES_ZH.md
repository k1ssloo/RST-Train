# RSI 算法级候选：形式化、核心局限与三个方案

写于 2026-09-03。数字来自 `TODO.md` 记录的单 shard 度量，未全量复核。

## 一、RST 原算法的形式化

记号

- 任务 τ = (I, E, S, V)。I 指令；E 初始环境；S = (s_1, …, s_L) 为 oracle 解，一串可执行命令；
  V: 终态 → {0,1}^m，m 个命名 check。终态 reward r(τ, x) = ∏_j V_j(x)；PPO 用 Σ_j V_j / m 一类的 shaping。
- oracle 轨迹：x^S_0 = init(E)，x^S_k = run(s_k, x^S_{k-1})。接受条件 A(τ) = 1[r(τ, x^S_L) = 1] ∧ 静态门。
- 学生 π_θ(a | h)，h 为历史，动作 a 含命令批与 claim ∈ {0,1}。rollout ξ ~ π(τ) 从 x_0 = init(E) 出发；
  pass rate p_π(τ) = E_ξ[r(τ, x_T(ξ))]。
- 任务池演化：T_{t+1} = Sel_caps({τ' = G(τ, o) : τ ∈ T_t, o ~ h(τ), A(τ') = 1})。G 为设计者，o ∈ O（40 算子），
  h 为 seed 特征加配额的启发式，Sel 按 p_{π_t}(τ) 的带与血缘/类别上限选种。
- 学生更新：RFT θ_{t+1} = argmax Σ_{τ∈T_t} Σ_{ξ~π_t(τ), r=1} log π_θ(ξ | I)（每任务上限）；
  PPO max E_{τ,ξ}[r̃(τ,ξ)]，起点恒为 x_0。
- 难度定义：D(τ) = 1 − p_π(τ)，辅以 |S| 与命令数。

耦合结构。π 进入任务演化的唯一通道是 Sel 里的标量 p_{π_t}(τ)：它只决定选哪个 seed，不决定施加什么变换，
也不决定变换加在何处。任务结构进入学生训练的通道为零：S 在接受之后被丢弃，V 只以标量进入 reward，血缘不进入训练。

核心局限的定位。五个候选位置里，根因是难度定义：D 是一个在任务边界上、从 x_0 出发的标量。它强制了其余四个问题。

- 状态分布：所有 rollout 从 x_0 起，到达第 k 阶段的概率是 ∏_{i<k} p_i，晚阶段技能的样本随深度指数衰减。
  论文 pass 90% → 2.5%、RL reward 0.11 → 0.14 就是这个衰减。
- 信用分配：终态标量落在百步轨迹上，没有机制说明哪个决策付出了代价。RFT 没有信用分配。
- 任务演化：G 对 π 盲，方向是"加可执行工作"，接受条件是"设计者可解"。池向设计者 LLM 能可靠实现的增量漂移，
  而不是向学生的边界漂移。
- 目标函数：学生优化 x_0 处的 E[r]；使一个任务可学的唯一手段是换一个任务。

一句话：RST 在任务内部没有任何把学生和 oracle 连起来的对象。oracle 是可解性证书，不是训练信号。
下面三个方案都是从不同侧面引入一个任务内部的学生–oracle 耦合变量。

## 二、三个候选

**方案一 · 接管曲线与辅助质量（Minimal Sufficient Assistance, MSA）**

1. 名称：最小充分辅助。
2. 核心新对象：接管成功函数 q_π(τ, k) = P_{ξ ~ π(· | I, x^S_k, ρ_k)}[r(τ, x_T) = 1]，k ∈ C ⊂ {0, …, L} 为 oracle
   轨迹上的切点（契约阶段或命令边界），ρ_k 为 s_1..s_k 及其输出的终端记录。导出量：接管距离
   κ_π(τ) = min{k : q ≥ 1 − ε}；辅助质量 M_π(τ) = (1/L) Σ_k [1 − q_π(τ, k)]，即成功曲线上方的面积，对非单调稳健。
   每个任务的状态变量从标量 p 变成函数 q(τ, ·)。
3. 与 RST 的本质区别：学生目标从 E_τ[q(τ, 0)] 变为 E_τ E_{k~μ_τ}[q(τ, k)]，μ_τ 由 q 自身决定并收敛到 δ_0；难度从 1 − p
   变为 M；教师目标从"增加 L"变为"每新增一条命令带来的辅助质量"。RST 的 oracle 只在接受时执行一次，这里 oracle 的每个
   前缀都是训练起点。
4. 形式化：
   - 接管状态 z_k = (I, x^S_k, ρ_k)。ρ_k 作为"他人会话"呈现，不伪造成学生自己的 JSON 轮次。
   - 学生目标 J(θ) = E_{τ~T} E_{k~μ_τ} E_{ξ~π_θ(·|z_k)}[r(τ, x_T)]，μ_τ(k) ∝ exp(−|q̂(τ, k) − 1/2| / β)，q̂ 由最近 rollout 估计。
   - 更新：任一策略梯度；GRPO 的组内基线按 (τ, k) 分组。评测永远在 k = 0。
   - 教师接受规则 A'(τ') = A(τ') ∧ q_π(τ', L_parent) ∈ [a, b]：把父任务做完交给学生，学生完成增量的概率落在中间带。
   - 教师目标 max_o [M(τ') L' − M(τ) L] / (L' − L)。
   - 伪代码：
     ```
     for round t:
       for τ in T_t:  estimate q̂(τ,k) on grid C, n rollouts each (bisection if monotone)
       train π on start-state mixture μ_τ
       for τ in T_t:  τ' = G(τ, o); accept iff A(τ') and q̂(τ', L_parent) ∈ [a, b]
     ```
5. 为什么不是工程改进：它改变学生看到的状态分布（从 x_0 变为 oracle 轨迹上的点）、改变难度量、改变接受规则；
   不依赖任何 prompt，只依赖 oracle 可执行这一事实。
6. 利用的结构：oracle solve.sh 的可执行性与阶段结构；血缘（L_parent 是天然切点）；Terminus-2 的上下文摘要意味着
   部署中的 agent 本来就在接管态运行，LHTB 的数百轮任务尤其如此。
7. 可检验预测（训练前）：
   - P1 q 对 k 在 ≥ 80% 任务上单调不减；若不成立，M 仍有定义但 κ 无意义。
   - P2 RST 晚轮任务的辅助质量集中在最后一个阶段，与失败时中位 60% 部分通过一致。
   - P3 对 RST 发布的父子对，q_base(τ', L_parent) 的中位数 > 0.8：把父任务做完后，基座模型能完成设计者加的增量。
     若成立，RST 的难度增长是长度的复合 ∏ p_i，不是新技能。RST 自身框架提不出这个预测。
   - P4 M 对从头 pass rate 的解释力在控制 log L 之后仍显著。
8. 最小实验：sweet 池 40 任务 × 5 切点 × 4 rollout = 800 次，基座模型，只测 P1 到 P4，本机 rootless docker 约两天。
   训练实验：200 任务、同 rollout 预算，基线 (i) 从 x_0 的 GRPO；(ii) 均匀 k 的接管训练；(iii) 用学生自身失败轨迹前缀
   代替 oracle 前缀；(iv) 直接在 oracle 命令记录上 SFT；(v) 教师用长度目标 vs 增量密度目标。
   指标：held-out 100 任务 k = 0 pass、TB2 子集、每 rollout 的 pass 增量。
9. 审稿人质疑：学生更新等于 reverse curriculum / Backplay / Salimans-Chen，回应靠 (ii)(iii)(iv) 与 P3；前缀泄露 oracle
   路线、学生只是在模仿，回应靠 (iv)；oracle 路线对学生不自然，回应靠 (iii) 与 k = 0 评测。
10. 失败的含义：q 平坦，说明难度不沿 oracle 轨迹局部化而是全局的（理解指令、建模环境），接管无意义；q 单调但训练
    不改善 q(·, 0)，说明技能不向前迁移，"会收尾不会开头"，组合性假设错误。

**方案二 · 可恢复性距离与不可返回点（Oracle Recoverability / Point of No Return）**

1. 名称：oracle 可恢复性信用分配。
2. 核心新对象：学生状态 x 到 oracle 流形的距离 d(x) = min{L − j : r(τ, run(S_{j+1..L}, x)) = 1}，∞ 表示没有任何
   oracle 后缀能从 x 完成任务。沿学生轨迹 ξ 定义不可返回点 PNR(ξ) = min{t : d(x_t) = ∞}，以及 claim 时刻的残余
   距离 d(x_T)。它是方案一的对偶：方案一是 oracle 前缀加学生后缀，这里是学生前缀加 oracle 后缀。
3. 与 RST 的本质区别：RST 的信用分配是终态标量或 check 计数；这里每个学生状态得到精确、无需学习的进度量，并把一条
   失败轨迹分解为可恢复前段、决定性动作 a_PNR、不可恢复后段。训练对象从"整条轨迹"变为三个策略：进展（d 下降）、
   停机（claim 当且仅当 d = 0）、恢复（从 d = ∞ 回到有限）。
4. 形式化：
   - 计算：在"后缀越长越可能通过"的单调假设下，d(x) 用二分法 O(log L) 次执行。
   - 停机目标 L_stop = E_t[BCE(claim_t, 1[d(x_t) = 0])]。
   - 进展：势函数 Φ(x) = −d(x)/L，策略不变塑形 F_t = γΦ(x_{t+1}) − Φ(x_t)。只作为对照基线，不是主张。
   - 决定性动作：在最后一个可恢复态 x_{PNR−1} 上，专家动作 a*(x) 为使 d 最小的 oracle 后缀的第一条命令；
     DAgger 式更新 min E_{x~d_π, d(x)<∞}[−log π(a*(x) | x)]，权重 w(x) ∝ 1[x 为 PNR 前一态]。
   - 恢复：从 x_{PNR..PNR+Δ} 出发 rollout，reward 1[∃ t : d(x_t) < ∞]。
5. 为什么不是工程改进：新状态变量 d，新分解 PNR，三个新的训练目标；改变的是信用分配的粒度与被训练的策略类。
   不是 DPO 数据构造，因为它在学生自己的状态上给出逐态监督。
6. 利用的结构：oracle 后缀的可执行性；发布的 231k 干净轨迹每条都有命令序列可在环境中重放；ctrf 的部分通过给出 d 的粗上界。
7. 可检验预测：
   - P1 在 claim 时刻，多数失败的 d(x_T) 有限且小（≤ 3 条 oracle 命令）："差几步就宣称完成"。与 92% 宣称、60% 部分
     通过一致，但 RST 只能报 0/1。
   - P2 PNR 位置集中在前 30% 步内，后段是无效徘徊；若 PNR 集中在末尾，失败是收尾问题而非路线问题，方案二退化为纯停机训练。
   - P3 学生中间态的可恢复率随 t 衰减但不塌到零；若多数中间态 d = ∞（学生路线与 oracle 结构性不同，例如文件名不同），
     流形太薄，方案不可用。
8. 最小实验：从发布轨迹取 200 条 Qwen3.5-27B 失败轨迹，沙盒重放命令，取 6 个等距状态加 claim 态，各二分 oracle 后缀，
   约 200 × 7 × log L ≈ 8,000 次短执行（后缀执行远短于完整 rollout）。只测 P1 到 P3。训练实验：停机头单独训练 vs 无；
   PNR 加权 DAgger vs 随机态 DAgger vs 仅 Φ 塑形。指标：k = 0 pass、false-claim 率、claim 时 d 的分布。
9. 审稿人质疑：d 是昂贵的精确 value function，学过的 critic 也能做，回应：RST 的 critic 在均值 0.11 的稀疏 reward 上
   无法定位，d 是证书级精确，实验直接比较；DAgger 加脚本专家是模仿学习，回应：新的是后缀可执行性判定决定专家何时有效，
   以及 PNR 分解；重放不确定性，回应：只用确定性任务，报告重放一致率。
10. 失败的含义：P3 失败说明 oracle 流形对学生路线太薄，oracle 不是学生状态的有效参照，方案一也要重审；P1 失败（d 大或 ∞）
    说明失败不是"差几步"而是路线错误，停机训练无用，重心转向方案一。

**方案三 · 以学生轨迹为基底的递归（Student-Anchored Recursion）**

1. 名称：学生锚定递归。
2. 核心新对象：递归的基底从设计者的 S 换成学生的成功轨迹 ξ*。子任务 τ' = G(τ, ξ*, o)，其 oracle S' = cmds(ξ*) ⊕ Δ，
   接受仍由执行 S' 与 V' 决定。
3. 与 RST 的本质区别：RST 的递归在设计者解上自我延展，池的不动点由设计者可实现性决定；这里递归在学生已能做到的事上
   延展，池按构造跟随学生边界。接管点 L_parent 处的前缀是学生自己的路线，消除方案一"oracle 路线不自然"的质疑。
   它改变的是任务演化规则的输入，不是加一个模块。
4. 形式化：T_{t+1} = Sel({τ' = G(τ, ξ*, o) : τ ∈ T_t, ξ* ~ π_t(τ), r(ξ*) = 1, A(τ') = 1, q_{π_t}(τ', |ξ*|) ∈ [a, b]})。
   学生更新同方案一，切点取 k = |ξ*|，即在自己的成功之后接管增量。
5. 为什么不是工程改进：递归算子的定义域从 (τ, o) 变为 (τ, ξ*, o)，池的极限分布随之改变；不依赖 prompt 细节，G 与 RST 相同。
6. 利用的结构：RST 释放的 61,575 条成功轨迹本身就是可执行 oracle；血缘。
7. 可检验预测：P1 同一父任务、同一算子下，学生锚定子任务在 L_parent 处的接管成功率落在中间带的比例高于设计者锚定
   子任务（后者的增量多为设计者易做、学生也易做，见方案一 P3）；P2 等增量长度下，学生锚定子任务的从头 pass 相对父任务
   下降更多；P3 多轮后池的 M 分布保持在中间带，而 RST 池的 M 向 1 漂移。
8. 最小实验：100 个有学生成功的父任务，每个用同一算子生成两版子任务（设计者 oracle vs 学生 oracle），各 4 次 rollout，
   比较 P1、P2。接受率必须报告：学生轨迹含探索命令，S' 更长更脆，接受率可能下降。
9. 审稿人质疑：学生轨迹作为 oracle 噪声大、含无效命令，可解性证书退化；多轮后可能收敛到学生的习惯而非任务本质。
   这是三个方案里最接近"换数据源"的一个，P1 与 P2 都成立才有资格称算法改进。
10. 失败的含义：P1 不成立说明增量难度与基底无关、完全由算子决定，方案一的教师目标应只作用于算子；P3 不成立说明学生
    锚定无法防止漂移，需要显式的 M 约束。

## 三、总评与顺序

苛刻地说：方案一的学生更新规则是已知的（reverse curriculum、Backplay），新的是 q 曲线与 M 这两个对象、接受条件 A'
与教师目标，最强的证据点是 P3，它直接检验论文"难度增长"的定义。方案二的更新规则接近 DAgger，新的是 d 与 PNR，最强
证据点是 P1。方案三是范式层面的变化，但最容易被读成换数据源。三者共享同一个基本对象：学生轨迹与 oracle 轨迹之间的
双向距离。RST 只有这两条轨迹的端点。

顺序：先做方案一 P3 和方案二 P1。两者都是测量，不需要训练，共用沙盒重放基础设施。P3 若成立，整个研究的叙事就成立：
RST 的递归增加的是长度，学生缺的是接管与停机。
